# VisualizeIT for iPhone

Native SwiftUI / AVFoundation source for iOS 17 and later. Open `VisualizeIT.xcodeproj` in Xcode 16 or later on macOS, select the VisualizeIT scheme, choose your signing team and a unique bundle identifier, then run on an iPhone. No package installation, XcodeGen, browser wrapper or hosted website is required.

This project has **not been compiled or run on an iPhone**. The Windows source pass does not establish compilation, camera support, visual parity or tracking quality. Android native implementation remains pending. Existing Unity sources are separate.

## Native flows

The camera workspace follows the six supplied visual references: glass header, gradient star, rainbow screen rim, Ask / Analyze / Design controls, translucent chat, design chooser, generator, and result panel. The system supplies the status bar, safe areas and permission prompt; no status bar is simulated. A black camera startup / denied state has actionable Settings access. Real camera content is not bundled as a fake preview.

Ask is a clearly scoped, deterministic local design helper. The reference generator retains its five object prompt chips, 500-character editor and “Generate image” button; the result panel retains only Regenerate and Upload. Pattern selection, capability explanation and PNG export live in Settings → Local design preview. The finite generator makes wood slats, color waves, dots or typography using native drawing; it does not create arbitrary objects. Select Typography in Settings to render your words. Submitting an unsupported object example reports the unavailable generator and offers local patterns or import. Generated artwork is 768 × 960 pixels; imported images are downsampled to at most 1024 pixels per edge. Local artwork and its pattern kind persist in Documents/Artwork and the latest is restored on launch. Use native PhotosPicker for import and ShareLink in Settings for export. No photos-library-wide permission or microphone access is requested.

Wood slats use a persistent transparent native SceneKit scene: 18 extruded wood slats, dark backing, procedural wood-grain materials, warm key lighting, pink/violet rim lighting and a soft floor ellipse. The finite panel spins upward on entry and rests at an oblique angle. One-finger drag turns it; two-finger drag moves it; pinch resizes it; twist rotates it. Context-menu and VoiceOver actions supply alternatives. Other finite patterns and imported images remain flat native artwork previews. This geometry is not an inferred object, reconstruction or tracked surface attachment. The exported PNG is the finite artwork, not a 3D model. Reduced Motion skips entrance movement; Reduced Transparency provides opaque glass surfaces. Scene playback stops while inactive and the view releases its scene when dismantled. SceneKit is available on the iOS 17 deployment target; newer SDKs may issue its deprecation warnings. Pixel comparison, scene lighting, large accessibility text sizes and physical-phone gestures remain unverified.

## Camera and tracking boundary

`CameraController` owns its AVFoundation capture session and callbacks on a serial queue. It uses the rear wide camera at VGA resolution. Preview alone rotates 90° and uses aspect fill. Output bytes stay in the unrotated, unmirrored landscape-right coordinate system. Camera selection uses `captureDevicePointConverted(fromLayerPoint:)`, which compensates preview crop and rotation and returns normalized unrotated image coordinates.

The output connection enables camera intrinsic matrix delivery when supported **before** starting capture. Each sample reads the camera-provided column-major `simd_float3x3` attachment. Its fx / fy / cx / cy and raw pixel dimensions form the calibration; no guessed intrinsics, artificial crop or rescaled K are used. Intrinsic delivery is hardware dependent. Missing calibration blocks admission. Calibration drift between session and frame disconnects the stream and requires new admission. These conventions need checking against captured JPEGs and the chosen device camera before mobile readiness can be claimed.

Settings → Tracking pipeline uses the versioned `/v1/native` API documented in `../docs/native-pose-contract.md`. Enter the HTTPS origin of a trusted operator, memory-only bearer token and an operator-admitted asset ID. Redirects are rejected. Temporary frame-upload consent defaults off, resets on backgrounding and is required before any session/frame request. Capability inspection checks the pinned model head `27e06a513713232f4ae542d50b8364a3bb319669451448e694bcd335a3fb9311` and live admission before session creation. Installed provenance can be unknown before backend initialization; a conflicting non-null hash blocks connection and a tracking pose is accepted only after the actual installed hash matches. The operator must independently supply a valid observed mask; a client tap is never promoted into a mask. Unconfigured service / missing asset / mask / calibration / admission returns an explicit blocked state.

This milestone restricts the operator to a trusted **local computer**: literal private / link-local / loopback IPv4, unique-local / link-local / loopback IPv6 (including mapped local IPv4), `localhost`, or valid `.local` hostnames. Network.framework IP parsing and explicit ranges reject public IPs and ambiguous IPv4 spellings. Public/cloud hostnames are rejected. TLS certificate validation is unchanged, so a local HTTPS certificate must already be trusted by iOS; there is no certificate bypass or HTTP fallback. Loopback refers to the iPhone itself, not the development computer. A valid `.local` name still requires a trusted local network and operator certificate. Cloud processing needs new human scope authorization.

After admission, capture → JPEG → authenticated URLSession frame request runs continuously with one request in flight and no frame queue; the next capture starts only after the response. VGA limits the longest edge to 640. Each response must match session, generation, sequence, timestamp, calibration/artwork revision, model provenance and valid pose conventions. A single published result owns the captured bytes, response and optional registered artwork render. Only this exact processed image/result pair is displayed. Current observed-mask contours (at most 32 segments / 2048 points) rotate with the same raster and appear as a thin gradient outline. Camera capture continues underneath; no returned pose or old mask is overlaid on a different live frame. A server-provided RGBA artwork render is displayed only when its frame, RGB hash, artwork revision and pixel dimensions match. Arbitrary locally generated artwork is not automatically registered to metric geometry; absent render is explicitly labelled unavailable. No fabricated outline or projected silhouette substitutes for foreground evidence. Response streaming stops at 6 MiB rather than buffering an unbounded body.

Disconnect, consent withdrawal, camera failure and backgrounding cancel pending work, invalidate the client generation, clear displayed tracking and request server deletion. Tokens and consent are cleared on backgrounding. Camera frames are not saved to disk. App-owned artwork PNGs remain local until the user exports them. The generic privacy manifest describes the local app; a production distribution must reassess disclosures for its configured operator and its actual data retention.

## Required macOS / device validation

If you do not own a Mac, the repository also includes a **manual-only** GitHub macOS build: Actions → Native iPhone build (manual only) → Run workflow. Its runner-usage confirmation defaults off. The workflow has no push, pull-request or scheduled trigger and was not run during this source delivery. A future explicitly confirmed run compiles the source and retains the toolchain, build log and unsigned simulator app for three days; it does not launch tests or perform inference. This uses the repository's GitHub Actions allowance/billing. The simulator artifact cannot be installed directly on an iPhone; signing and actual-device distribution remain separate.

Run `xcodebuild -project native-ios/VisualizeIT.xcodeproj -scheme VisualizeIT -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build` on macOS before treating this as a compiled app. Then verify camera grant / denial / Settings recovery, interruption / background / resume, intrinsic attachments and exact JPEG calibration on the intended iPhone and OS; test native Photos import/export, low-memory images, accessible text/motion/transparency, all six reference layouts, network rejection/cancellation and calibrated live admission. Validate tracking and surface rendering with independent device evidence; source wiring is not accuracy evidence.
