# YCB dataset-reference projection diagnostic (post-run, CPU only)

`tools/workbench_ycb_dataset_evaluate.py` is a **dataset-reference diagnostic** of the three
terminal supplemental YCB runs. It compares the new head (27e06) against the frozen base
(f7d1) at 110 frames per role, with the original `sam2-workbench-01` masks:

| Object | Clip | Run |
| --- | --- | --- |
| 2 | `dev-ycb-003-cracker-box` | `run-20261021T030702-475adc39` |
| 4 | `dev-ycb-005-tomato-soup-can` | `run-20261021T031729-0986ef46` |
| 18 | `dev-ycb-040-large-marker` | `run-20261021T032932-539343a7` |

## Scope

- BOP YCB-Video reference poses, masks and depth are dataset labels, **not independent
  human truth**.
- Fixed flags: `independent_human_accuracy=false`, `phone_attachment_verified=false`,
  `development_only=true`, full printed-UV correspondence `inconclusive`, human gates
  `unverified`.
- Existing `report.accuracy`, human gates, masks, poses, caches, controls, maps and
  preparation are never written. Output goes only to a fresh directory under
  `.cache/video-workbench/derived`.
- Inference, automatic RGB preparation and any opening-prompt correction never read
  reference labels and never receive these results.

## Two phases

```
# Phase 1. Never reads reference labels. It hashes evaluator.json BYTES against its pin
# without parsing them, and opens no scored mask, depth or pose.
python -B tools/workbench_ycb_dataset_evaluate.py prepare \
    --out .cache/video-workbench/derived/dataset-reference/plan-v1

# The parent pins plan.json's SHA-256 externally and writes the terminal seal (below).

# Phase 2. A separate process.
python -B tools/workbench_ycb_dataset_evaluate.py evaluate \
    --plan .cache/video-workbench/derived/dataset-reference/plan-v1/plan.json \
    --expected-plan-sha256 <external pin> \
    --terminal-seal <parent seal path> \
    --out .cache/video-workbench/derived/dataset-reference/eval-v1
```

There is no `--force`, no automatic approval and no seal generated by the tool.

### What `prepare` authenticates

- **Pins:** `inference.json`, SHA `9b936de3…5403945`, and that it binds the evaluator SHA
  `c54534d6…1b870`.
- **Reviewed map:** `tools/workbench_ycb_execution_controls.reviewed.json` and, per object,
  the execution-control `model.glb`, `metric-bundle.json` and sidecar against the map's
  candidate-GLB and bundle pins.
- **Run identity:** for each run:
  - `run.json`, `results.jsonl`, `report.json`, `neural-artwork.json` and every
    `stages/*.json` are hashed;
  - the run, clip, `regression` mode and the exact roles (`primary_neural`,
    `frozen_baseline`) match;
  - the 110 scheduled frames equal `s%06d` of the inference scored frames, in order;
  - the config has the mask set, the map SHA equal to the current map file, the sidecar
    SHA, and `execution_only_prepared_cad`;
  - the report is `completed`, with both role stages `completed` at 110 frames.
- **Rows:** an exact `(role, frame)` join, with duplicates, extras, missing or reordered rows
  rejected. Every row passes `FrameResult` validation and carries:
  - the run, clip and `source_frame_index` equal to `frameId`;
  - the same decoded-image identity for both roles;
  - head 27e06 (primary) or `frozen_base_pose_head` with no installed head (baseline);
  - base f7d1, the candidate GLB SHA and origin `integer_centers`.
- **RGB binding:**
  - Every scored RGB file must match the inference `rgb.sha256` pin. The clip frame's
    `image_sha256` must equal that pin.
  - The RGB is decoded with the pipeline's exact convention (`bench.workbench_cli.FrameReader.read`):
    `cv2.imdecode(raw, IMREAD_COLOR)` → contiguous BGR→RGB → `workbench_geometry.array_sha256`,
    which hashes `dtype.str|shape|bytes`.
  - Both result roles' `image_sha256` must equal *that frame's* decoded pixel identity. Two
    matching role hashes for the wrong frame fail.
  - Bindings are frozen per frame in `run.rgb[frame_id] = {path, file_sha256, pixel_sha256}`.
    `clip.json` is hashed. Only RGB is decoded here, never labels.
- **Artwork and mask set:**
  - `neural-artwork.json`: its schema, `record_sha256` (the canonical body), units in metres,
    the GLB SHA and origin, and `effective_K` equal to every frame's `cam_K`.
  - The SAM mask manifest equals the run's mask-stage canonical SHA and declares
    `evaluator_inputs_read=false`.

### What `prepare` freezes (`plan.json` + `samples-object-0000NN.json`)

- **Anchor:** `X = Σ bary_i · V[face][i]`, using the `neural-artwork.json` marker on the
  candidate GLB (metres, loaded with the same `glb_mesh` the runs used, at 15728 faces).
- **CAD samples:** 256 per object, generated as follows:

  ```
  rng = np.random.Generator(np.random.PCG64(20261021 + object_id))
  u_face = rng.random(256)                                    # float64, drawn first
  face = min(searchsorted(area_CDF, u_face, side='right'), F - 1)  # int64
  r = rng.random((256, 2))                                    # float64, drawn second
  s = sqrt(r[:, 0])
  bary = (1 - s, s * (1 - r[:, 1]), s * r[:, 1])
  position = bary @ triangle
  ```

  Areas are in float64, in face order. The positions (`<f8`), face IDs (`<i8`) and
  barycentrics (`<f8`) are hashed. These are CAD samples, **not independent landmarks**.
- **Also frozen:** per-frame `cam_K`, `depth_scale` and RGB SHA (from inference); the metric
  specification and constants; the flags; and the limitations.
- **Dependency and runtime closure:**
  - `plan.sources` holds the SHA-256 of every imported project helper: `bench/__init__.py`,
    `bench/vision.py`, `bench/workbench_contract.py`, `bench/workbench_geometry.py`,
    `bench/workbench_neural.py`, and this tool. Each module must load from its repository path.
  - `plan.runtime` records `python_executable`, `python_version`, `numpy`, `pillow`, `opencv`,
    `opencv_module` and `platform`.
  - The tool's own SHA does not stand in for its imports.
- **Sample-file hashes:** `samples-object-000002.json` → positions `57bd4aa5726b…`;
  `samples-object-000004.json` → `8c86e82153cf…`; `samples-object-000018.json` →
  `226bf7d07986…`. These come from an in-memory run of `build_plan`, so the plan is not yet
  written.

```json
{

  "plan_sha256": "<external plan pin>",
  "tool_sha256": "<sha of tools/workbench_ycb_dataset_evaluate.py; equals plan.tool_sha256>",
  "inference_sha256": "9b936de31c5511e3644e065538dedf47d0cdcd22f2ba17cee083e75a25403945",
  "evaluator_sha256": "c54534d6835653eb367f8d6fee34bd56cd3417056d48f5468d4f6e7d565b1870",
  "reviewed_map_sha256": "<plan.pins.reviewed_map_sha256>",
  "runs": {"2":  {"run_id": "run-20261021T030702-475adc39", "files": {"<exact copy of plan.objects['2'].run.files>": "..."}},
           "4":  {"run_id": "run-20261021T031729-0986ef46", "files": {"...": "..."}},
           "18": {"run_id": "run-20261021T032932-539343a7", "files": {"...": "..."}}},
  "gpu_worker_terminal_observed": true,
  "observed_by": "<parent>", "observed_at": "<time>",
  "statement": "parent observed the original GPU worker terminal before sealing"

```

**What `evaluate` checks before it reads any reference label:**

1. The plan matches the external pin, and the plan directory inventory is exact.
2. The tool SHA equals the plan's.
3. The seal is exact, as above. A missing, stale, partial or non-terminal seal is refused.
4. A full rehash of the closure matches the plan:
   - the plan, the samples and inference;
   - the map and the evaluator bytes;
   - every run file, `clip.json`, the control files and the mask manifest;
   - **all 330 scored RGB files**;
   - **every helper source** (the imported helper set must also be identical).

   In addition, `runtime_identity()` must equal `plan.runtime`.
5. The output path is fresh, and the budgets hold: 1 GiB derived, 1 GiB free reserve, and a
   16 MiB output cap.

Any failure in these checks exits with code 2 and writes nothing.

**After those checks:** only then does it read `evaluator.json`. That file must have:
- a label kind containing "not independent human truth";
- per object, the model SHA equal to the PLY pin;
- frames **key-joined** to the plan. Reordering is tolerated; duplicate, missing or
  unscheduled frame IDs are rejected;
- per frame, the RGB SHA, `cam_K` and `depth_scale` equal to inference.

It then streams the cached `mask_visib` and `depth` PNGs that the evaluator references, and the
sealed SAM masks. Each file's hash is checked at read time; nothing is downloaded.

**Malformed labels:** a hash-authenticated label that fails to decode with an expected Pillow
error (`UnidentifiedImageError`, `DecompressionBombError`, `OSError` including truncation,
`ValueError` or `SyntaxError`) becomes `label_decode_failed:<Error>`. The frame's rows and pose
diagnostics are kept, and reference visibility and overlap become unknown or null.
Unrelated programming errors still propagate.

**Final rehash:** every input, every label read, the **terminal seal file** and the runtime
identity are checked again and must match.

## Metrics (frozen before any reference read)

### A. Anchor

- Projection uses the exact frame K (origin `integer_centers`, assumed and not optimised).
- Poses: `T_pred` is the row pose in metres; `T_BOP` is R row-major plus t in mm × 0.001,
  converted once.
- An improper R is never repaired: it gives `invalid_reference_pose` or
  `invalid_prediction_pose`.
- Error: native Euclidean pixels, and `px720 = native × 720 / H`, which is ×1.5 at H = 480.
- **Reference eligibility** (valid R, z > 0, inside `[-0.5, W-0.5) × [-0.5, H-0.5)`) does not
  depend on the prediction.
- **Prediction statuses:** `ok`, `no_tracking_pose`, `invalid_prediction_pose`,
  `prediction_behind_camera` or `prediction_out_of_image`. Anything other than `ok` keeps its
  row with a null error.
- **Per role:**
  - the conditional median and P95 over measured errors;
  - coverage at ≤ 5 and ≤ 10 px720, over **all reference-eligible frames**;
  - status counts over all 110 frames.

  A paired-frame subset is reported separately.

### B. CAD samples

- The same 256 point identities are projected under both poses. There is no symmetry
  minimisation or registration.
- **Reference-eligible points** (z > 0 under `T_BOP`) are fixed first and are each frame's
  denominator, even when the prediction is missing.
- **Fields per role and frame:**
  - `status`: `complete`, `partial`, `missing_prediction`, `no_paired_points`,
    `no_reference_points` or `invalid_reference_pose`;
  - `prediction_status`, `reference_eligible_points`, `paired_points`,
    `prediction_behind_camera_points`, `prediction_invalid_points`, `paired_fraction`;
  - **failure-aware** `coverage_le_5px720` and `coverage_le_10px720`, computed over the
    reference-eligible points;
  - `conditional_median_px720` and `conditional_p95_px720`, which cover paired points only.
- **Example:** 255 points behind the camera plus one perfect survivor gives `partial`, a paired
  fraction of 1/256 and coverage of 1/256. It is never an unqualified success. A missing pose
  keeps its denominator, with coverage 0.
- **Role summary (`B_cad_samples`):**
  - `frames_complete`, `frames_partial`, `frames_without_paired_points`;
  - `median_paired_fraction`;
  - the median and minimum over frames of failure-aware coverage;
  - the clearly labelled `conditional_*` quantiles of the per-frame medians and P95s.
- Points, frames and objects are never pooled. Hidden surfaces are included. This is not BOP
  MSPD.

### C. Anchor, reference-visible subset

Visibility is decided from the reference only, before any prediction. All of these must hold:
- a valid R, z > 0 and in bounds;
- no nearer source-mesh intersection (tolerance 1e-5 m, excluding the anchor's own face);
- BOP `mask_visib` is positive at the pixel `floor(u + 0.5)`;
- measured depth (raw × `depth_scale`, in mm) is within max(5 mm, 1% of the measured value).

Every rejection reason is reported. A missing, hash-mismatched or wrongly shaped mask or depth,
or zero depth, means visibility is `unknown`. There is never a prediction or
projected-silhouette fallback.

### D. Availability and display

- All 110 frames per role, counting separately:
  - frames with a tracking pose;
  - frames with `render_state = rendered`;
  - frames with `rendered_pixels > 0`, plus the median `rendered_pixels` among those.
- Pose projections do not prove that artwork rendered correctly.
- Optional overlap between the sealed SAM mask and the dataset `mask_visib`: IoU, and the
  fraction of the SAM mask outside the reference. These are null when a label is missing.
  Each overlap row carries `reference_mask_status` and `sam_mask_status`.
- Wrong-surface events and recovery correctness remain `null` and unverified.

## Output

`dataset-reference-projection.json` (`workbench_ycb_dataset_reference_projection_v1`)
contains:
- the flags, limitations and metric specification;
- the pins, `runtime` and `sources`, the plan SHA and the seal SHA;
- `hash_closure`: before-read and after-read hashes, label-read hashes, and the terminal seal
  hash before and after;
- per object:
  - the anchor visibility row for every frame, with counts and reasons;
  - the SAM-vs-dataset overlap rows and summary;
  - per role: all 110 A rows, B rows and D rows, plus the summaries and the paired subset.

Values are finite or null; Infinity is never emitted. If evaluation fails after the seal, the
output directory holds only `failure.json`, with the stage and the labels read so far.

## Limitations

- The CAD geometry and calibration (K, assumed origin) are shared by prediction and reference.
- These are development objects with reference-derived onboarding seeds. The models may
  have had public YCB-Video training exposure.
- The labels are not independent human labels.
- Surface identity is fixed and not minimised over symmetries.
- A single anchor cannot certify orientation, footprint or occlusion.
- The CAD samples are not landmarks.
